Results with status computed and the source "this catalogue's solver" come from exhaustive searches run by tools/solve.ts in the site's repository. A search that runs out of its step budget proves nothing and is not recorded. Every search is exhaustive in the sense stated below, so the results are proofs by computer, as reliable as the code.

Order and smallest rectangles

For k = 2, 3, ... copies, every rectangle of area k times the piece size is searched for a tiling, filling the first empty cell in reading order. The first k for which some rectangle can be tiled is the order, because every rectangle holding fewer copies was ruled out. All rectangles of that area are searched, so the recorded smallest rectangles are complete, and a tiling of each is stored.

Corner test

The corner of any rectangle must be covered. For a depth d, the test tries to cover every cell within d rows and columns of a corner with copies that stay inside the rectangle. It does this for every possible rectangle size near the corner: each side either shorter than d (so the far wall is within reach) or at least d (then the wall is ignored, which only allows more arrangements). If no arrangement exists for any size, the piece tiles no rectangle.

The test is sound but not complete. Pieces such as the S tetromino force a staircase that leaves any finite corner region, so the test cannot rule them out; such pieces are listed as undecided until a stronger argument is entered.

Checks

The solver was verified against Dahlke's complete list of orders through hexominoes and against Reid's data for heptominoes and octominoes: every order it can reach agrees, and the corner test never rejects a piece known to tile a rectangle.
